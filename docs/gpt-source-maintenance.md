# GPT 源头调研维护

维护对象：`1337816143/MyDotWork` 的 GPT 订阅供货、原账号代充和相关手机号验证研究。2026-11-03 起继续按既有证据标准增量维护。最新专题通过 `data/workbench-catalog.json` 中 `project-1` 的日期报告定位；本次起点为 `publications/research/2026-11-03/`。

## 调研目标

- 优先寻找可持续提供本人原号、单件单月订阅的上游，保留无需代理前置费的要求。
- 沿用全部必需支付、汇兑、开票等费用合计不超过 170 元的 Plus 采购筛选线；准确套餐、周期和数量分别比较。此线不是 Pro 或手机号验证服务的统一价格上限。
- 核对批发门槛、阶梯价格、经营及开票主体、款项与供货关系、转售授权、交付条件和售后。零售可下单、店名含“源头”、低价格或存在 API 都不能单独证明上游资格。
- 同时维护实际可用的服务线索：手机号验证、原号登录、Session/Token 前提、Apple/Google 内购、网页付款与卡密交付；不把服务线索直接纳入已核实上游名单。

## 每轮执行

1. 读取最新仓库 HEAD、本文件、最新日期报告与已有候选，先判断尚缺哪些会影响购买选择的证据。
2. 针对性读取商家自有商品页、教程和条款；平台机制用官方资料核对。核查新来源时记录发现渠道与原始 URL。
3. 为每条事实保存实际观察日期、准确 SKU、币种、周期、数量、付款附加费、票费、适用账号与证据状态。页面自标更新时间和本轮读取时间分别保存。失败访问单列，不能用新日期覆盖旧事实。
4. 区分四类结果：网页确实展示的事实、商家自己的承诺、由公开材料作出的推断、已完成的真实交易或测试。没有实际采购、收票或验证，就继续标记未实测；未知费用用 `null`，不得以零补齐。
5. 有实质变化时，新增日期报告 HTML 和结构化证据，写清旧值、新值、来源和影响。更正错误时保留原观察与更正理由。未发现变化时记录本轮无新增，不制造空提交或重复推荐。
6. 把新报告加入发布白名单和工作台目录，更新站点版本、CHANGELOG 与总库最新入口；历史报价、旧报告和聊天档案按原字节保留，除非本次任务明确涉及其更正。现有 126 条报价表不混入接码价格。
7. 执行仓库现有构建和相应验证，通过后以非强制更新提交。重新读取远端 HEAD；如有并发提交，以新基线合并本轮改动，不能覆盖其他工作。
8. 检查对应提交的 Actions 和 Pages 成果。准确区分已提交、构建通过和实际发布；出现阻塞须说明具体原因，不宣称已经完成。

## 持续任务与通知

按已设置的自动任务定期检查公开证据。历史轮次曾采用半小时检查；当前自动任务最高支持每小时一次，维护任务按每小时检查实质变化安排。每轮是一次有边界的核查，不代表持续在线监控所有商家。

有新的可信源头、费用或批发条件变化、开票/授权证据进展、手机号验证适用性变化、服务失效或足以改变选择的售后变化时，更新仓库并给出简短通知与报告/提交链接。没有实质变化时不反复推送旧名单。访问失败只记录为本次未取得正文，不自行宣称网站倒闭或停止供货。

公开网页研究、整理、仓库提交和现有 Pages 发布属于日常维护。本任务未包含采购付款、提交账号凭据、联系商家、销售或对外承诺；这些动作须有相应明确授权。公开文件仅保存研究事实与公开来源，不包含账号秘密、私人对话或内部工具记录。

## 发布入口

- 报告源文件：`publications/research/YYYY-MM-DD/`
- 精确字节与 SHA-256 白名单：`scripts/build_publications.py`
- 工作台检索：`data/workbench-catalog.json`，映射 `project-1`
- 总库最新补充入口：`src/template.html`
- 站点版本：`VERSION` 与 `CHANGELOG.md`
- 构建：`python scripts/build.py`
- 验证：以 `.github/workflows/pages.yml` 中现有步骤为准，保持历史哈希、公开边界和链接检查。

生成的 `dist/` 和 `src/index.html` 不提交。每条来源的观察日期独立保存；站点发布版本不等于全库重新核价。
