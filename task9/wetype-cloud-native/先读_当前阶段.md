# 微信输入法原候选框英文注释 · 云端工程阶段包

## 现在能做什么

这是源码、测试和诊断准备包，**尚未实现微信原候选框里的英文显示**。

已完成：
- 按真实中文候选原文精确查词的小核心：开发 → development、学习 → learning、词典 → dictionary
- 保留候选 ID、原索引、原文和顺序；不改排序，不把英文上屏
- 异步请求、输入上下文、会话、修订、分页、进程创建身份和模块 SHA-256 检查
- 一键停止核心时撤销旧结果、清空内部候选与显示状态；旧鼠标映射不能继续生效
- GCC 严格警告编译和 27 个合成测试，共 4,810 次断言通过
- ASan + UBSan 通过；容器不支持本次 LeakSanitizer，因此没有泄漏检测通过结论

生产版本白名单目前为空，真实 WeType 适配器一律拒绝启用。不能把这些测试当成微信实测。

## 官方接口调查

Windows 有公开的 IMM/TSF 候选接口。当前探针已加入只读 ImmGetCandidateListW，从本测试编辑器输入上下文读取候选元数据，只保留上述三个固定演示词的精确命中。微信实际是否暴露这些数据还没有实测。

读取候选的接口不等于能在微信自己的候选窗里增加一行英文。TSF 的自行绘制选项会改为应用画界面，不符合本任务要求。尚未查证到 WeType 官方原框扩展 SDK；这不等于断言它不存在。具体 SDK 名称或官方文档链接可改变实现路线。

## 使用与撤销

- Linux 核心测试：core/build-gcc.sh
- Windows 核心测试：在 Visual Studio 开发者命令提示符中运行 core/build-msvc.cmd
- Windows 只读编辑器：在已获准的临时 Windows 测试环境，用 Windows PowerShell 5.1 运行 probe/RunProbe.ps1；执行策略不允许时保留错误，不关闭保护或绕过策略
- 只输入 kaifa、xuexi、cidian 三个虚构测试场景；不输入真实聊天、密码或个人词库
- 关闭编辑器即可停止；没有开机启动、服务、计划任务或输入法注册项
- 本包没有安装器；删除解压目录即可移除本阶段文件
